§1 Framing

What "Day 2" actually means for an agentic enterprise.

Day 1 is the design. Day 2 is everything that happens after the first agent fires its first inference in production — and it is architecturally harder than Day 1.

TOGAF Phase H
Architecture Change Management

TOGAF defines Phase H as the ongoing process of monitoring the architecture for performance, compliance, and change drivers — and deciding whether to trigger a new ADM cycle. For the AE, this means each of the four process pillars must continuously report its architecture conformance status to the Enterprise Architecture Board (EAB).

GCP Cloud Adoption Framework
Six Governance Pillars

Google's CAF defines six operational governance pillars for production cloud environments: Security, Privacy, Compliance, Reliability, Performance Efficiency, and Cost/FinOps. Day 2 design is the engineering expression of these pillars applied to all four AE process pillars — each pillar instantiated as a concrete control plane, not a policy document.

Google SRE Model
Error Budgets & Toil Reduction

Google SRE teaches that reliability is a product feature, not an operations afterthought. For an enterprise AI platform, this means every agent, every model, and every HITL checkpoint has an SLO. Error budgets govern how aggressively new model versions can be deployed. Toil — manual, repetitive, automatable work — is metered and eliminated first.

The Day 2 thesis: An agentic enterprise that can design itself but cannot govern itself at runtime is architecturally incomplete. The Autonomous Enterprise Platform's Day 2 design closes that gap — with a single governance control plane that operates above all four process pillars, enforces the same compliance and reliability contract across all of them, and is itself governed by a formal Architecture Board running TOGAF Phase H continuously.

2.2 GCP CAF — Six Governance Pillars Instantiated for the AE

Each pillar is a concrete control plane, not a documentation section. Every pillar applies uniformly across all four process pillars.

Pillar 01 · Security

BeyondCorp zero-trust enforced at the org level. No implicit network trust. All agent-to-agent calls authenticated via Workload Identity Federation — no service account keys.

BeyondCorp Enterprise VPC Service Controls Cloud Armor WAF SCC Premium Workload Identity
Day 2 Control: Security Command Center Premium runs continuous Asset Inventory and Threat Detection across all four domains. Findings ≥ HIGH auto-create an incident in Cloud Operations and pause the affected agent's Pub/Sub subscription.
Pillar 02 · Privacy

All PII and PHI confined within VPC-SC perimeter. CMEK encryption — ClaraVis holds the keys (Cloud KMS, europe-west3). Data residency enforced via Org Policy, not application logic.

Assured Workloads CMEK / Cloud KMS Cloud DLP VPC-SC Perimeter
Day 2 Control: Cloud DLP Discovery scans all four domains' BigQuery datasets on a 24-hour schedule. Any un-tagged PII discovered auto-triggers a Data Governance quarantine event (M-08 pattern) and pages the domain's Data Steward.
Pillar 03 · Compliance

EU AI Act Annex III registry maintained at the EAB level — not per domain. Every high-risk AI model across all four suites is registered, versioned, and mapped to its HITL checkpoint and Model Card.

Vertex Model Registry BigQuery Audit Log Cloud Logging Sinks Policy Controller
Day 2 Control: GKE Policy Controller (OPA Gatekeeper) enforces that no Kubernetes deployment in any domain project can reference an ML model image that is not present in the enterprise Vertex Model Registry with an approved Model Card. "Ghost model" deployments are structurally impossible.
Pillar 04 · Reliability

SLOs defined per agent, per HITL checkpoint, and per ML pipeline. Error budgets govern deployment velocity. SLO burn rate alerts defined in Cloud Monitoring — not in Slack.

Cloud Monitoring SLOs Error Budget Policy Chaos Engineering Multi-region Spanner
Day 2 Control: Error Budget Policy: if 50% of any domain's monthly error budget is consumed, all non-emergency releases to that domain are frozen at the Artifact Registry level (Terraform CODEOWNERS enforcement). Reliability recovers before velocity resumes.
Pillar 05 · Performance

Vertex AI endpoint latency p99 is a first-class SLO for every model in production. Feature Store read latency ≤ 50ms at p95. Pub/Sub message delivery latency ≤ 500ms cross-domain.

Vertex AI Endpoints Feature Store SLOs Cloud Trace Pub/Sub Metrics
Day 2 Control: Cloud Trace distributed tracing is mandatory for all agent-initiated inference calls. Trace sampling rate 100% for HITL-path requests (compliance requirement), 1% for autonomous-path requests. Latency regression detected within 5 minutes via Cloud Monitoring alert policy.
Pillar 06 · FinOps / Cost

Every GCP resource carries four mandatory labels: ae-domain, ae-module, ae-environment, ae-cost-centre. No resource without all four labels can be provisioned (Org Policy + Terraform sentinel).

Budget Alerts Committed Use Discounts GreenOps Scheduling Cost Allocation Labels
Day 2 Control: GreenOps (M-06) is elevated from an AS-module to an enterprise-wide scheduler. All four domains submit their batch workload manifests to GreenOps, which optimises the cross-domain compute schedule against the GCP Cloud Carbon Footprint API — reducing emissions and cost simultaneously.

§4 SRE Model & SLOs

Error budgets govern deployment velocity.

Google SRE doctrine applied to an agentic enterprise: every agent, every ML model endpoint, and every HITL checkpoint has a quantified reliability target. Error budgets are the mechanism that prevents the platform from being deployed into unreliability.

Google SRE Principle applied to the AE: "The error budget provides a clear, objective metric that determines how unreliable the service is allowed to be within a single quarter." For the AE, this means: if FinRisk Sentinel's error budget is exhausted — meaning it has been unavailable beyond its SLO target — no new FinRisk model version may be promoted to production until reliability is restored. This is enforced by Artifact Registry tag policy, not by a manager's discretion.

Error Budget Policy — Formal Definition
Threshold 1 — 50% Budget Consumed

Release Freeze for affected domain

All non-emergency releases to the affected domain project are blocked at Artifact Registry. Only P0 security patches bypass. Freeze lifted when error budget recovers above 50%. Terraform CODEOWNERS enforces the block.

Threshold 2 — 75% Budget Consumed

Domain SRE Incident Opened

Automated PagerDuty-equivalent alert to Domain SRE on-call. Incident requires root cause identification within 4 hours. HITL timeout policy relaxed to 120 minutes (from 60) to reduce HITL as a latency source.

Threshold 3 — 100% Budget Consumed

EAB TOGAF Phase H Review Triggered

Error budget exhaustion triggers a mandatory TOGAF Phase H Architecture Review for the affected domain. The domain's deployment to production is paused until an Architecture Change Request is approved by the EAB and a new baseline is established.

Critical Runbook — P0: Audit Ledger Failure
T+0 min — Detection

Cloud Monitoring alert fires

BigQuery write error rate > 0.01% triggers ae-audit-ledger-failure alert. All Pub/Sub subscriptions for agent write operations are automatically paused via Cloud Monitoring notificationChannels — alert → Cloud Function → Pub/Sub admin API.

T+5 min — Triage

SRE On-Call: Isolate failure scope

Check: is failure in BigQuery dataset, VPC-SC perimeter, or IAM binding? Cloud Logging query: resource.type="bigquery_dataset" severity="ERROR". Identify affected domain(s). All HITL approvals in flight are held in Spanner state — no data loss.

T+15 min — Mitigation

Failover to Cloud Spanner audit replica

Enterprise Spanner instance (multi-region: eur3) acts as hot failover for audit writes. Agent write path has a circuit-breaker that auto-detects BigQuery unavailability and routes to Spanner within 30 seconds. Agents resume. BigQuery backfilled on recovery.

T+60 min — Recovery

Validate audit continuity + resume writes

Confirm Spanner → BigQuery backfill completes with zero gap. Verify record count parity. Re-enable Pub/Sub subscriptions. EAB Post-Incident Review required within 48 hours. ADR update if root cause requires architectural change.

§7 TOGAF Phase H: Architecture Change Management

How the architecture governs its own evolution.

TOGAF Phase H is not a gate at the end of the ADM — it is a continuous monitoring loop that runs in parallel with operations. For the AE, it is the mechanism by which the Enterprise Architecture Board decides whether a change to any of the four process pillars requires a new ADM cycle or can be handled as a managed change.

ADR-017 (Day 2 — new): The enterprise Pub/Sub schema registry is owned by the EAB, managed in Apigee, and versioned independently of domain code. No domain team may create a cross-domain topic without an approved schema version in the registry. This prevents the event fabric from becoming an undocumented, untestable inter-domain dependency graph — the single largest operational failure mode in event-driven enterprise architectures.
ADR-018 (Day 2 — new): GreenOps (M-06) is promoted from an Autonomous Quote-to-Cash module to an Enterprise Platform Service. All four process pillars submit batch workload manifests to the GreenOps scheduler. GreenOps optimises the cross-domain compute schedule against the GCP Cloud Carbon Footprint API. Rationale: carbon reduction and cost reduction are the same optimisation target. Centralising the scheduler achieves 40% better carbon efficiency than four independent domain-level schedulers competing for the same low-carbon compute windows.
ADR-019 (Day 2 — new): The Data Governance module (M-08) is promoted from an Autonomous Quote-to-Cash module to an Enterprise Platform Service. All four domains share a single TFX Validate schema registry and a single quarantine pipeline. Rationale: a financial anomaly detected in the Finance domain (ae.finance.anomaly.detected.v1) often traces to a data quality failure that originated in the Procure-to-Pay domain's invoice ingestion. Domain-isolated data governance cannot catch cross-domain lineage failures. Enterprise data governance can.

§9 Day 2 Operational Roadmap

How the Autonomous Enterprise reaches full operational maturity.

§10 Day 2 Design Principles

The rules the enterprise cannot break.

Principle D2-01
Governance is infrastructure, not process

Every governance control in this document is enforced by a GCP service, a Terraform policy, or a Cloud Build gate — not by a committee decision or a policy document. If it cannot be enforced by code, it is not a governance control. It is a guideline.

Principle D2-02
Domain autonomy is bounded, not absolute

Each process pillar has a defined autonomy envelope — the set of architectural decisions it can make without EAB approval. Breaking changes to cross-domain contracts (event schemas, shared services, IAM policies) are always above the autonomy boundary. Domain velocity is preserved within the envelope.

Principle D2-03
The audit ledger is the enterprise's ground truth

Every consequential event — agent action, HITL decision, model inference, cross-domain event, compliance obligation satisfaction — is written to the enterprise BigQuery audit ledger before any downstream effect executes. The audit record is not a report. It is the system of record.

Principle D2-04
Error budgets are the only deployment gate that matters

Release cadence is governed by error budgets, not by approval committees. A domain whose SLO error budget is healthy has earned the right to deploy. A domain whose budget is exhausted has not — regardless of feature priority or business pressure. This principle is enforced by Artifact Registry policy.

Principle D2-05
Regulatory deadlines are hard constraints on the scheduler

GreenOps, FinOps, and performance optimisation are desirable. MDR Art. 87 SLAs, HITL timeout policies, and daily forecast refresh deadlines are not. Hard-deadline jobs carry an immutable defer: false flag in the GreenOps manifest. No scheduler — carbon-optimised or otherwise — may override a hard regulatory or SLO deadline.

Principle D2-06
Shared services are enterprise infrastructure, not domain shared code

The BigQuery audit ledger, Pub/Sub event fabric, Vertex AI Feature Store, and Data Governance module are enterprise infrastructure — owned and SRE'd by the Platform team, not by any domain. Domain teams are consumers, not co-owners. Breaking changes to shared infrastructure require an EAB Major ACR and a new ADM cycle.
